Fiscal Agent 接入说明

这是 Fiscal 给联网 Agent 使用的公开说明页。页面不包含任何密钥、账单或个人数据。

MCP endpoint： https://mcp.fiscal.linotsai.top/mcp

机器配置： /.well-known/fiscal-agent.json

标准使用顺序

  1. Agent 读取本页或 discovery JSON，使用 POST /auth/challenges 创建 session 申请，拿到 4 位 pairing_code。
  2. Agent 告诉用户：“请在批准页批准配对码 XXXX”。批准页是固定网址 https://console.fiscal.linotsai.top/agent/approve/，用户输入 Google Authenticator 当前 6 位验证码。
  3. Agent 使用返回的 poll_token 作为 X-Fiscal-Poll-Token 轮询申请，拿到短期 session_token。
  4. Agent 用 Authorization: Session <session_token> 调用 MCP（initialize、tools/list、tools/call 都校验）。Session 失效或未知时任何 /mcp 请求都返回 HTTP 401、error.code 为 session_expired，可用 ping 低成本探测。会话空闲 2 小时失效，最长 8 小时。
  5. 读取、分析和暂存账单可以直接完成。要提交到账本时，Agent 用当前 Session 创建 write_window 申请，用户在同一批准页再批准一次；之后 30 分钟内该 Session 的所有提交都不再需要批准。

每个验证码只能批准一次；用户连续批准两条申请时，需要等下一个验证码（约 30 秒）。同一来源最多同时挂 2 条会话申请，同一 Session 只保留最新一条写入窗口申请。

网关重启或发布后，所有 Session 与写入窗口都会失效（返回 session_expired）；重新创建申请即可。同一来源最多同时挂 2 条会话申请；输错验证码只会触发限流，不会撤销申请。

1. 创建 session challenge

POST https://mcp.fiscal.linotsai.top/auth/challenges
Content-Type: application/json

{"kind": "session", "client_label": "my-agent", "intent": "整理本周账单"}

201 Created
{"challenge_id": "fiscal_challenge_v1_…", "poll_token": "fiscal_challenge_v1_…",
 "kind": "session", "expires_at": "2026-10-16T12:10:00+00:00", "pairing_code": "K7P2",
 "approval_url": "https://console.fiscal.linotsai.top/agent/approve/"}

scopes 可选，默认即全部 Session 权限：read:reports、read:ledger、stage:imports、export:reports。申请 10 分钟内有效；待批准申请过多时返回 429 too_many_pending。intent 会公开显示在批准页上，不要写入账单明细或个人信息。

2. 轮询拿 token

GET https://mcp.fiscal.linotsai.top/auth/challenges/{challenge_id}
X-Fiscal-Poll-Token: {poll_token}

200 OK  {"challenge_id": "…", "kind": "session", "status": "pending", "expires_at": "…"}
200 OK  {"challenge_id": "…", "kind": "session", "status": "approved", "expires_at": "…",
         "session_token": "fiscal_session_v1_…"}

write_window 申请批准后返回 write_window_expires_at，不返回 token。建议每 3–5 秒轮询一次。

3. 调用工具

POST https://mcp.fiscal.linotsai.top/mcp
Authorization: Session fiscal_session_v1_…
Content-Type: application/json

{"jsonrpc": "2.0", "id": 1, "method": "tools/call",
 "params": {"name": "fiscal_list_accounts", "arguments": {}}}
  • 金额字段 amount_minor 是整数分（12.34 元 = 1234）；occurred_at 必须带时区，例如 2026-10-14T12:00:00+08:00。
  • 先用 fiscal_list_accounts / fiscal_list_categories 拿到账户与分类 ID，再生成候选。
  • 还款到固定账期信用账户（cycle_mode 不是 on_demand）时，候选必须带 credit_cycle_id，从该账户的 open_cycles[].cycle_id 里选；随借随还账户不要带。
  • 工具错误以 isError: true 返回，error.code、error.message 来自后端；error.details.http_status 与 backend_details 帮助定位原因。

4. 开启写入窗口再提交

POST https://mcp.fiscal.linotsai.top/auth/challenges
Authorization: Session fiscal_session_v1_…
Content-Type: application/json

{"kind": "write_window", "intent": "提交本周 12 笔"}

201 Created  {"challenge_id": "…", "poll_token": "…", "kind": "write_window", "pairing_code": "R4MZ", …}

用户批准后，同一个 Session 在 30 分钟内直接调用提交工具，参数里不需要任何授权字段：

{"jsonrpc": "2.0", "id": 7, "method": "tools/call",
 "params": {"name": "fiscal_commit_import_batch",
            "arguments": {"batch_id": "3f6c1d2e-8a4b-4c1e-9f00-2b7d5e6a9c10",
                          "expected_version": 2, "idempotency_key": "commit-2026w42-01"}}}
  • 窗口未开或已过期时，提交、新建账户/分类以及现金流计划的新建/确认/入账/取消都返回 write_window_required，重新申请写入窗口即可。窗口只属于发起它的 Session；只读 Session（如用户面板）不能申请写入窗口。
  • 提交是幂等的：网络错误或后端 5xx 时，用完全相同的参数（同一 idempotency_key）重试，不会重复入账。

工具一览

  • fiscal_get_monthly_report / fiscal_get_yearly_report：月报、年报；余额未知的账户带 opening_balance_status 等状态字段。
  • fiscal_list_accounts / fiscal_list_categories：账户（含固定账期信用账户的未结清账期）与分类。
  • fiscal_create_account / fiscal_create_category：新建钱包/账户（cash 现金与微信/支付宝余额、debit 储蓄卡、credit 信用账户，期初余额为整数分）与收支分类（可带 aliases、examples 帮助归类）。与提交一样需要已开启写入窗口；有期初欠款的信用账户须给 opening_balance_as_of_date 与 opening_due_date。
  • fiscal_search_ledger：分页搜索已入账交易。
  • 报销：fiscal_list_reimbursable_expenses 找到可报销的已入账消费（available_minor 为还能报的金额）→ fiscal_create_reimbursement 把一笔或多笔消费挂到同一个报销方（每笔可只报一部分），默认立即提交，待回款自动出现在待入账；钱回来后用 fiscal_record_reimbursement_receipt 记回款（可分多次，写入实际金额、时间与到账账户）；确定收不回来用 fiscal_cancel_reimbursement_outstanding。fiscal_list_reimbursements 查看状态与未回款金额；草稿用 fiscal_submit_reimbursement 提交。写操作需要写入窗口；若网络中断结果不明，用完全相同的参数和 idempotency_key 重试，网关会返回原结果、不会重复入账；不要换新 key 重试，除非先用 fiscal_list_reimbursements 确认上次确实没有记上。
  • fiscal_list_cash_flow_items / fiscal_get_cash_flow_outlook：未来待入账计划（含信用卡账期与报销回款；传 month 看已入账/已取消历史）与未来 30 天现金流汇总。
  • fiscal_create_cash_flow_item → fiscal_confirm_cash_flow_item → fiscal_settle_cash_flow_item；不会发生的用 fiscal_cancel_cash_flow_item。新建的计划状态为“预计”，必须先确认才能入账；入账写入实际金额（整数分）、实际时间（带时区）和账户，生成正式账目。这四个写操作都需要写入窗口，并带 idempotency_key（新建与入账）以便安全重试。
  • fiscal_create_import_batch → fiscal_validate_import_batch → fiscal_commit_import_batch；不要的批次用 fiscal_ignore_import_batch；fiscal_get_import_batch 查看状态与校验错误。
  • fiscal_export_report：月度或年度 CSV（base64）。

Agent 应遵守的边界

  • 不得向用户索取验证码：只告诉用户配对码，验证码由用户本人在批准页输入。也不索取或记录个人 Fiscal API key。
  • 验证码、Session token 和 poll token 都不得写入日志、账单备注或公开回答。
  • 先导入、校验、展示摘要并得到用户确认，再申请写入窗口；窗口内也只提交用户已确认的批次。
  • 个人 Fiscal API key 是人工使用的 break-glass 兜底钥匙，不属于 Agent 自动流程。

如果 Session 过期，重新创建 session challenge 即可；不需要重新配置 Agent。

用户批准页面

打开 TOTP 批准页面（固定网址，可加入书签）。页面只在有待批准申请时显示输入框；只有能提供当前验证码的人才能批准操作。
