Fiscal Agent 接入说明

这是 Fiscal 给联网 Agent 使用的公开说明页。页面不包含任何密钥、账单或个人数据。

MCP endpoint： https://mcp.fiscal.linotsai.top/mcp

机器配置： /.well-known/fiscal-agent.json

标准使用顺序

  1. Agent 读取本页或 discovery JSON，使用 POST /auth/challenges 创建 session challenge。
  2. Agent 把返回的 approval_url 发给用户；用户打开页面，用 Google Authenticator 输入当前 6 位验证码。
  3. Agent 使用返回的 poll_token 作为 X-Fiscal-Poll-Token 轮询 challenge，拿到短期 session_token。
  4. Agent 用 Authorization: Session <session_token> 调用 MCP（initialize、tools/list、tools/call 都校验）。Session 失效或未知时任何 /mcp 请求都返回 HTTP 401、error.code 为 session_expired，可用 ping 低成本探测。会话空闲 2 小时失效，最长 8 小时；验证码每 30 秒变化不会中断已建立的会话。
  5. 读取、分析和暂存账单可以直接完成。真正提交到账本前，Agent 为本次请求创建 operation challenge，用户再次输入一次验证码；该写入授权只允许匹配的请求使用一次，有效 30 分钟。

网关重启或发布后，所有 Session 与未使用的写入授权都会失效（返回 session_expired / operation_invalid）；重新创建 challenge 即可。

1. 创建 session challenge

POST https://mcp.fiscal.linotsai.top/auth/challenges
Content-Type: application/json

{"kind": "session", "client_label": "my-agent", "intent": "整理本周账单"}

201 Created
{"challenge_id": "fiscal_challenge_v1_…", "poll_token": "fiscal_challenge_v1_…",
 "kind": "session", "expires_at": "2026-10-14T12:10:00+00:00",
 "approval_url": "https://console.fiscal.linotsai.top/agent/approve/?challenge=fiscal_challenge_v1_…"}

scopes 可选，默认即全部 Session 权限：read:reports、read:ledger、stage:imports、export:reports。challenge 10 分钟内有效。

2. 轮询拿 token

GET https://mcp.fiscal.linotsai.top/auth/challenges/{challenge_id}
X-Fiscal-Poll-Token: {poll_token}

200 OK  {"challenge_id": "…", "kind": "session", "status": "pending", "expires_at": "…"}
200 OK  {"challenge_id": "…", "kind": "session", "status": "approved", "expires_at": "…",
         "session_token": "fiscal_session_v1_…"}

operation challenge 批准后返回的是 operation_token。建议每 3–5 秒轮询一次。

3. 调用工具

POST https://mcp.fiscal.linotsai.top/mcp
Authorization: Session fiscal_session_v1_…
Content-Type: application/json

{"jsonrpc": "2.0", "id": 1, "method": "tools/call",
 "params": {"name": "fiscal_list_accounts", "arguments": {}}}
  • 金额字段 amount_minor 是整数分（12.34 元 = 1234）；occurred_at 必须带时区，例如 2026-10-14T12:00:00+08:00。
  • 先用 fiscal_list_accounts / fiscal_list_categories 拿到账户与分类 ID，再生成候选。
  • 还款到固定账期信用账户（cycle_mode 不是 on_demand）时，候选必须带 credit_cycle_id，从该账户的 open_cycles[].cycle_id 里选；随借随还账户不要带。
  • 工具错误以 isError: true 返回，error.code、error.message 来自后端；error.details.http_status 与 backend_details 帮助定位原因。

4. 提交前的写入授权

先算 request_digest：把将要发送的提交参数（不含 confirmation_token）与工具名组成 {"arguments":<args>,"tool":"fiscal_commit_import_batch"}，用 UTF-8、按键名排序、无空格、不转义非 ASCII 字符的 JSON 序列化（Python：json.dumps(obj, ensure_ascii=False, sort_keys=True, separators=(",", ":"))）后取 SHA-256 十六进制。

序列化结果：
{"arguments":{"batch_id":"3f6c1d2e-8a4b-4c1e-9f00-2b7d5e6a9c10","expected_version":2,"idempotency_key":"commit-2026w42-01"},"tool":"fiscal_commit_import_batch"}
request_digest = e86efbf7e4c592ae17d55011737f73b5a2e14925c981e68d59abe5b14ef37d98
POST https://mcp.fiscal.linotsai.top/auth/challenges
Authorization: Session fiscal_session_v1_…
Content-Type: application/json

{"kind": "operation", "scope": "commit:imports",
 "request_digest": "e86efbf7…7d98", "intent": "提交本周 12 笔，合计 1,234.56 元"}

用户批准、轮询拿到 operation_token 后，原样发送同一组参数，token 放在 params._meta.fiscal_operation_token：

{"jsonrpc": "2.0", "id": 7, "method": "tools/call",
 "params": {"name": "fiscal_commit_import_batch",
            "arguments": {"batch_id": "3f6c1d2e-8a4b-4c1e-9f00-2b7d5e6a9c10",
                          "expected_version": 2, "idempotency_key": "commit-2026w42-01"},
            "_meta": {"fiscal_operation_token": "fiscal_operation_v1_…"}}}
  • operation_token_missing：没带 token 或放错位置。operation_invalid：token 未知（可能网关已重启）。operation_mismatch：参数或 Session 与批准时不一致，参数改动后必须重新申请。operation_expired / operation_used：过期或已用过。
  • 后端明确拒绝（4xx，例如版本冲突）会消耗本次授权；网络错误或后端 5xx 结果未知时授权保留，30 分钟内可用完全相同的参数重试（提交本身幂等）。

工具一览

  • fiscal_get_monthly_report / fiscal_get_yearly_report：月报、年报；余额未知的账户带 opening_balance_status 等状态字段。
  • fiscal_list_accounts / fiscal_list_categories：账户（含固定账期信用账户的未结清账期）与分类。
  • fiscal_search_ledger：分页搜索已入账交易。
  • fiscal_create_import_batch → fiscal_validate_import_batch → fiscal_commit_import_batch；不要的批次用 fiscal_ignore_import_batch；fiscal_get_import_batch 查看状态与校验错误。
  • fiscal_export_report：月度或年度 CSV（base64）。

Agent 应遵守的边界

  • 只向用户索取 Google Authenticator 当前验证码，不索取或记录个人 Fiscal API key。
  • 验证码、Session token、poll token 和 operation token 都不得写入日志、账单备注或公开回答。
  • 先导入、校验、展示摘要，再请求用户批准最终写入；不要跳过预览。
  • 个人 Fiscal API key 是人工使用的 break-glass 兜底钥匙，不属于 Agent 自动流程。

如果 Session 过期，重新创建 session challenge 即可；不需要重新配置 Agent。

用户批准页面

打开 TOTP 批准页面。只有持有本页链接并且能提供当前验证码的人才能批准操作。
