# Fiscal v1.5.2 Build 27 用户语言快修记录

> 日期：2026-08-23（Asia/Shanghai）
> 范围：macOS 与 iOS 正式前端
> 原则：界面只服务于用户理解、决定和完成任务；工程实现细节留在代码与审计记录中。
> 版本：营销版本保持 `1.5.2`，构建号由 `26` 提升为 `27`。

## 审查结论

v1.5.2（26）虽然已完成参考设计的布局和能力修复，但正式界面仍大量沿用设计、后端和 Agent 施工语言。用户被迫理解内部结构、协议字段和恢复机制，尤其在导航、状态说明、AI 记账、账单导入、报表、分期、系统与设置页中形成额外认知负担。

本次快修不改变业务能力、不改变 Backend，也不删除安全校验；只调整用户界面暴露的信息层级，并移除不应由普通用户填写的内部标识输入。

## 已处理的问题

| 类别 | 原问题 | Build 27 处理 |
| --- | --- | --- |
| 导航与结构 | “脊柱、检查器、工作台、工作区、权威稿”等面向设计或 Agent 的概念出现在正式界面 | 改为“账目、详情、导入、设置、概览”等用户熟悉的任务名称 |
| 数据来源说明 | “服务端事实、服务器读回、客户端推定、数据修订”等实现边界被直接展示 | 只说明“当前数据、已保存、尚未提供、请刷新确认”等用户需要知道的状态 |
| 内部标识 | 操作编号、交易 UUID、请求键、请求体、哈希、数据修订号、对象版本号可见 | 从界面正文和成功/失败说明中移除；内部仍保留用于安全提交和排错 |
| 原始状态 | 未知枚举值、状态码、原因码和错误码直接透出 | 映射为可理解的中文状态；未知值统一显示“暂时无法识别”并给出下一步 |
| 手工 ID 输入 | 商户关联要求输入交易 ID；现有消费转分期要求输入交易 UUID | 删除这两个面向内部对象标识的入口；保留正常的新消费分期流程 |
| AI 记账 | “提案、审核字段、人工执行、写入结果、提案版本、质量诊断”等 Agent 工作流占据主界面 | 改为“待确认内容、检查并修改、确认记账、记账结果”；移除原始诊断和代码字段 |
| 账单导入 | 哈希、脱敏证据、提供方执行、快照/版本等技术过程成为主要说明 | 改为选择账单、确认隐私处理、检查识别结果、确认导入和处理失败项 |
| 报表 | “下钻、口径事实、修订绑定、导出快照”等分析实现术语过多 | 改为查看明细、统计方式、数据更新时间和导出结果 |
| 分期/信用 | 计划版本、周期 UUID、内部生命周期状态和警告码可见 | 只展示金额、期数、账户、应还日期、当前进度与可执行操作 |
| 报销/现金流/核对 | 预览令牌、fresh read、版本冲突字段等内部机制写进操作说明 | 保留预览与确认的两步安全流程，但用“重新加载最新数据、检查变化、再次确认”表达 |
| 系统与数据 | 凭证生成、协议版本、运行状态内部字段和技术恢复文案过多 | 改为备份、恢复、存储、连接、安全状态及明确的用户行动 |
| 成功与错误提示 | 提示重点是系统做了什么请求、是否重放、如何读回 | 提示重点改为用户的操作是否完成、当前结果、未完成事项和下一步 |

## 明确保留在内部的能力

以下能力没有因为删文案而被删除：版本一致性校验、幂等键、结果不明保护、冲突接管、服务器预览失效、离线写入限制、generation/token 竞态守卫、错误展示链路、typed service 和原始协议字段。它们继续保障数据安全，但不要求用户理解其工程名称。
