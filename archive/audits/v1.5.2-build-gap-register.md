## B7 独立复审收口 — completed

- 真实状态语义：成功/服务器读回、未知仅展示、归档只读各用独立组件；归档组件只用于确实 archived 或 voided 的对象。Ledger reconciled 与 PendingWrites 不再伪装为归档，分期未知状态为不可操作的仅展示状态。
- 冲突事实：正式 iOS 还款、报销、现金流先保存提交前快照，再强制 fresh GET；只展示能从服务响应逐项比对的旧/新字段。读取失败、服务未返回字段或提交前未保留快照时，changes 为空，只说明当前版本/修订与能力限制，不编造字段级对照。
- 真实读取与同步：分类只显示 fresh GET 的当前账目事实和缺少 preview token 的限制；Mac 启动不静默 replay pending writes，账单导入恢复具备可见离线门禁，月报按 generation/owner 丢弃旧读取。
- 正式根壳与控件：`V151IOSWorkspace` 消除固定金额字体；金额不缩放、不换行、不截断，超宽值仅在受约束的局部水平区域完整阅读。AX5 下摘要纵向重排，底栏保持三个可达入口。业务量级 root fixture 对请求月份返回完整 `Asia/Shanghai` 月报；独立 F2-A `Int64.max` route 证明局部横滚不撑宽整页。正式路径已替换无语义 loading/原生控件语法。

## 需要后端契约后才能彻底关闭的能力

### CAP-152-01 · 还款服务器预览缺失

- 关联：F151-02。
- 已核实：现有还款写入可读取账户、账期和版本并提交，但没有返回 preview token 与服务端影响清单的独立预览端点。
- 前端处置：卡内要求最新账期事实、明确来源/目标账户与金额后才能确认；界面明示“当前服务没有独立预览令牌”，不生成假影响清单。
- 真正完成条件：Backend 提供版本绑定的 repayment preview/commit 契约，输入变化后旧 token 失效。

### CAP-152-10 · 分类变更服务器预览缺失

- 关联：F151-02、F151-09。
- 已核实：单笔与批量分类只有 `GET transaction` 和直接版本化 `PUT transaction`；没有返回影响清单或 preview token 的分类预览端点。
- 前端处置：先 fresh GET 展示服务器当前账目、当前版本和明确的能力限制；确认动作明确为直接分类写入。批量路径仅展示提交范围与逐笔结果，不把客户端摘要称为预览。
- 真正完成条件：Backend 提供版本绑定的 category preview/commit 契约，包含变更影响清单并在输入或版本变化后使 token 失效。

### CAP-152-02 · 现金流确认预览令牌缺失

- 关联：F151-02。
- 已核实：现有手工现金流条目支持读取最新事实并以 expectedVersion 确认，但没有独立 preview token。
- 前端处置：先强制重新读取“影响”事实，再提交版本化确认；系统投影或不可定位对象保持禁用并解释原因。
- 真正完成条件：Backend 提供现金流确认预览及 token-bound commit。

### CAP-152-03 · 待同步写入原地编辑缺失

- 关联：F151-05。
- 已核实：PendingWrites 支持排队、重放、移除、冲突与结果不明状态，但没有安全修改已排队 request body 的公开接口。
- 前端处置：允许移除并重新决定；不把“移除后新建”伪装成原地编辑。
- 真正完成条件：为可编辑写入类型定义校验、幂等键继承/替换和 owner 归属规则，并提供 typed edit API。

### CAP-152-04 · 普通账户检查点历史缺失

- 关联：F151-05。
- 已核实：账户详情接口提供当前余额、类型、版本、归档与信用约束，没有检查点时间序列。
- 前端处置：展示当前服务器事实，并明确说明历史暂不可用。
- 真正完成条件：Backend 提供账户 checkpoint history 或等价稳定事实接口。

### CAP-152-05 · 报表分类口径事实不完整

- 关联：F151-03。
- 已核实：分类汇总只返回总消费、商户退款、净消费；个人预计承担、个人实际承担、预计报销、已收报销没有对应分类分布。
- 前端处置：当前口径无分类事实时显示“服务暂未提供”，另起标题保留真实净消费分类供验算和下钻，不把净消费改名复用。
- 真正完成条件：Backend 为七个口径返回同期间、同修订号的分类汇总及稳定钻取能力。

### CAP-152-06 · 报表日趋势序列缺失

- 关联：F151-03。
- 已核实：月/年报表契约没有按日时间序列。
- 前端处置：支出镜头保留清晰的未提供状态，不从本地账目拼接一条看似权威的趋势。
- 真正完成条件：Backend 提供与七口径一致、版本绑定的日趋势序列。

### CAP-152-07 · 预测与债务周期序列缺失

- 关联：F151-03。
- 已核实：报表只提供期末信用欠款和期末待报销总额，没有现金流预测、未来分期或账期债务时间序列。
- 前端处置：现金流与债务镜头只展示现有汇总和账户快照；未来序列位置明确标注服务未提供。
- 真正完成条件：Backend 提供可追溯到同一 data revision 的预测及债务周期事实。

### CAP-152-08 · 钻取逐行事实不完整

- 关联：F151-03。
- 已核实：钻取行返回总消费、商户退款、净消费，不返回逐行已收报销、个人实际承担、账户名称、作废或归档状态。
- 前端处置：双端表格只显示真实三列，并在表头上方说明缺失字段；不从其他端点拼接可能错版的事实。
- 真正完成条件：Backend 扩充 revision-bound drill row schema，或提供可在同一版本安全联结的稳定字段。

### CAP-152-09 · 访问密钥过期与撤销原因不可区分

- 关联：F151-16。
- 已核实：Backend 对缺失、过期或已撤销的访问密钥统一返回 `invalid_access_key`，错误语义只有“invalid or revoked”，没有失效原因或到期时间字段。
- 前端处置：启动门显示“访问密钥已过期或被撤销”的合并状态，停止进入实时工作区，并要求重新解锁；不根据本地时间或旧凭证状态猜测具体原因。
- 真正完成条件：Backend 返回稳定、非敏感的失效原因枚举（至少 expired/revoked）或等价可审计元数据。
