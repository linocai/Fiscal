# Fiscal v1.5.1 前端独立审计

> 日期：2026-08-22（Asia/Shanghai）
> 基线：`main` / tag `v1.5.1` / `2f47d4e`
> 范围：macOS 与 iPhone 正式 live root；只读审计
> 权威：`Fiscal 前端设计启动/` 中的 Handoff、静态高保真与可点击原型

## 1. 结论

v1.5.1 已建立正确的颜色令牌、macOS 三栏基础壳、iPhone“今日 / 记一笔 / 账目”基础壳，以及多数 typed service 与安全状态模型。但其正式前端仍未达到参考设计验收：关键差距集中在决策原位完成、镜头语义、页面覆盖、状态真值表达、对象专属信息结构和 AX5 重排。

下列 17 项是 v1.5.2 的完整修复输入。编号在 `PROJECT_PLAN.md` 中保持不变。

## 2. A 级：验收阻断

### F151-01 · macOS 镜头不是脊柱筛选器

- 影响：macOS。
- 当前：缺少“归档”镜头；信用、报销、导入会离开主脊柱；“需要决定”退化为全部账目；“待同步”点击即重放。
- 权威差距：七个镜头都应收敛中间脊柱，并保留右侧检查器语境；待同步镜头应展示队列而不是直接执行。
- 主要位置：`V151MacWorkspace.swift`。
- 完成定义：补齐七镜头；每个镜头有真实筛选结果、计数、空态；待同步只展示并由明确动作发起重放；对象深链仍可从行或检查器进入重活页面。

### F151-02 · iPhone 今日卡缺少卡内就地解决

- 影响：iOS。
- 当前：注意项只提供“选择分类 / 查看 / 稍后”，信用卡只提供“查看账期”，主要动作跳转至其他工作区。
- 权威差距：分类、还款、报销收款、现金流确认应在卡内完成编辑、服务器预览、确认、冲突接管与凭证翻面。
- 主要位置：`V151IOSWorkspace.swift`、Today/Credit/Reimbursements/CashFlow 的现有模型与展示组件。
- 完成定义：四类卡均在当前 Today 队列原位完成；任一输入变化使预览失效；冲突覆盖整卡；成功后卡面变为真实凭证；“稍后”重排而不是仅在本次 View 生命周期中消失。

### F151-03 · 报表构图未实现权威稿

- 影响：macOS、iOS。
- 当前：模型已有四镜头和七口径，但正式 View 仍是通用三栏/Section 文本页。
- 权威差距：缺少顶部四镜头、主指标舞台、七口径对照、分类分布、趋势，以及现金流/债务的专用布局；术语仍混用“报告”。
- 主要位置：`Features/Reports/**`。
- 完成定义：两端按高保真重组；保留服务端事实与真实 drill capability；七口径作为中性量值；统一称“报表”。

### F151-04 · 系统与数据、设置覆盖不完整

- 影响：macOS、iOS。
- 当前：系统与数据主要是加密 Archive 导出；设置主数据只有账户、分类、商户。
- 权威差距：缺少服务版本、schema 兼容性、data revision、备份/恢复/磁盘状态、最近验证与恢复演练；缺少统一归档区、AI Provider/识别质量及修改口令入口。
- 主要位置：`Features/DataSecurity/**`、`Features/Settings/**`、`Features/AI/**`、Bootstrap/Session 可用能力。
- 完成定义：把后端已提供的事实完整呈现；无后端能力的动作保留可见禁用态和原因，不伪造；按参考形成系统接管页和设置分组。

### F151-05 · 通用账户详情与独立待同步队列缺失

- 影响：macOS、iOS。
- 当前：普通账户点击仅过滤账目；iOS 没有通用账户详情；iOS 待同步只在 Today 内显示，macOS 待同步镜头不展示队列。
- 权威差距：缺 i-08 和 i-16 的完整层级与状态。
- 主要位置：AppShell、Ledger、MasterData、PendingWrites。
- 完成定义：普通账户详情可从两端进入；展示余额、类型、检查点、归档状态和可用动作；待同步队列支持排队、同步中、冲突重决、结果不明、编辑/移除和批量凭证。

### F151-06 · Dynamic Type AX5 未落地

- 影响：以 iOS 为主，兼顾 macOS 可访问性字号。
- 当前：固定 `Font.system(size:)`、固定行高、单行截断和水平动作组较多；没有动态字号分支。
- 权威差距：未执行“元信息换行 → 按钮纵排 → height 改 minHeight → 图标顶对齐”，不能证明 AX5 无截断。
- 主要位置：DesignSystem、AppShell 和全部正式 View。
- 完成定义：语义字体支持 Dynamic Type；AX3–AX5 按权威顺序重排；金额保持单行；macOS 脊柱摘要允许两行且不破坏列对齐。

## 3. B 级：明显差距

### F151-07 · 归档视觉语法未全局贯彻

- 当前：部分列表只追加“已归档”或降低透明度。
- 完成定义：所有归档对象统一为灰度、45°斜纹、“归档 · 只读”标签和恢复入口；作废与归档不混用。

### F151-08 · 离线乐观值没有完整真值标注

- 当前：已有待同步分组和数量，但受影响汇总没有“含 N 项未同步”，也未并列上次服务器确认值。
- 完成定义：顶部持久离线条、受影响数值虚线标记、服务器确认值、队列与批量同步凭证在两端一致。

### F151-09 · 冲突状态缺少字段级新旧对照

- 当前：通用组件主要显示 expected/current version 和通用说明。
- 完成定义：冲突面说明变更字段、旧值、新值、“未做任何修改”；重新读取后让原预览失效并用新版本重算。

### F151-10 · 账单导入信息结构偏通用管理界面

- 当前：macOS 虽有三栏但中栏使用默认 List；iOS 是纵向长页。
- 完成定义：macOS 明确“页面证据 / 行 / 处置”三段；iOS 逐行分步审阅，显示批次进度、完整处置集、证据降级、预览与部分完成凭证。

### F151-11 · 重型业务页缺少对象专属构图

- 影响：信用、分期、报销、现金流、AI、对账等。
- 当前：多数仍表现为同一套 NavigationStack、Section、Picker 或稀疏分栏。
- 完成定义：不改变模型和服务语义，按各自高保真重新建立指标层级、时间结构、预览后果、冲突与凭证面。

### F151-12 · 加载态与原生控件破坏统一语言

- 当前：通用骨架只有三条灰条；多处使用旋转 ProgressView、默认 Form/List、系统 bordered 控件；iOS 底栏使用模糊材质。
- 完成定义：加载骨架保持最终几何；正式主路径去除不受控默认样式；底栏使用纸面和发丝线；深色模式完全由 Fiscal 令牌控制。

### F151-13 · 部分量值被错误表现为收支

- 当前：报表七口径被映射为 inflow/outflow；未来计划金额也沿用已发生收支的符号和颜色。
- 完成定义：量值统一 neutral；未来/计划保持 yellow 未定语法，不伪装为已入账事实。

## 4. C 级：收口与精度

### F151-14 · iPhone 重型入口隐藏且集合不一致

- 当前：报表、导入、报销等藏在省略号菜单，账目菜单缺少对账入口。
- 完成定义：按原型在账目页提供明确的重活入口，菜单集合和命名与 IA 一致。

### F151-15 · iPhone 底栏图标和交易详情仍偏系统占位

- 当前：今日和账目使用相同方框图标，没有待办徽标；交易详情是标准全高导航 Sheet。
- 完成定义：使用权威语义图形、待办徽标和自定义详情底板/抓手/层级。

### F151-16 · 启动门状态与信息不完整

- 当前：access key 过期、撤销、无效归入通用需要口令；底部缺服务版本；没有修改口令入口。
- 完成定义：区分口令错误、未设置、过期、撤销、离线、服务未就绪；显示服务版本；提供真实可用或明确禁用的修改口令入口。

### F151-17 · macOS 窄窗口比例失衡

- 当前：约 1100pt 宽时脊柱被左右栏挤压，空态相对过大。
- 完成定义：1000pt 最小宽度仍保持脊柱可读，检查器和索引按参考优先级收缩，1440×900 保持基准比例。

## 5. 已确认对齐、不得回退

- Fiscal 三色语义和深色基础令牌。
- macOS 自绘三栏和顶栏的基础方向。
- iPhone“今日 / 记一笔 / 账目”三入口。
- CNY 两位金额、等宽数字、Asia/Shanghai。
- typed services、服务端事实、preview/commit 分离、幂等与 generation 守卫等现有安全边界。
- 正式界面不得改为 HTML/WebView，不得以静态合成数据替代 live 数据。

## 6. 审计限制

- macOS 使用 v1.5.1 已安装正式应用做了实际窗口核验；截图含私人财务信息，未写入仓库。
- iOS 以 v1.5.1 正式源码和未变化功能页的既有 QA 图为主进行核验。
- 本报告是设计验收审计，不替代后续 AX5、深色模式、窄宽度和完整交互的构建后验证。
