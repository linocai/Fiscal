# Fiscal Agent-first 改造方案

日期：2026-10-10（Asia/Shanghai）  
状态：方案已确定，未施工  
当前生产基线：V2.4.0 Build51

## 1. 目标

Fiscal 的真实使用方式是每周或每十天由 Agent 批量整理账单，月底查看本月支出和分布。因此产品从“需要用户主动打开的原生记账 App”调整为：

**Fiscal Ledger Service + MCP Server + Web Console**

- FastAPI/PostgreSQL 后端、统一账本、账户/负债规则、报表、历史数据和 AI 提案机制继续作为唯一事实源。
- 新增受控 MCP 层，让授权 Agent 通过工具提交、校验、查询和（在授权条件满足时）确认账单。
- 新增轻量网页控制台，用于待确认批次、月底报告、账本搜索、导出和访问密钥管理。
- iOS/macOS 原生 App 以 Build51 为冻结基线，不再新增产品功能；在网页连续完成真实月度闭环前保留可回退安装包和源码。

## 2. 稳定边界

### 保留

- 现有 ledger、accounts、categories、credit、installments、reimbursements、cash flow、reports 和 archive 能力。
- 金额使用元输入、Int64 分存储，业务日期使用 Asia/Shanghai。
- AI proposal 的版本、幂等、撤销、人工确认和审计语义。
- 现有月报、年报、CSV 及历史快照兼容。

### 调整

- 以“导入批次”作为 Agent 工作单位；批次内包含多条候选记录和每条记录的校验结果。
- MCP 只调用现有 service 层，不直接访问数据库，不暴露任意 CRUD 或 SQL。
- 网页主流程固定为：待确认、月度报告、账本搜索、设置/导出。
- 原生端冻结，不为 MCP/Web 迁移重写 SwiftUI，也不把网页功能先复制进原生端。

### 第一阶段不做

- 删除原生 App、删除历史表或迁移现有账本。
- 自动把 Agent 识别结果直接写入正式账本。
- 多用户、团队协作、公开注册和第三方账单自动同步。
- 新的复杂财务规则、PDF 导入、多人报销或新的原生导航。
- 用 Excel 替代数据库作为事实源；Excel 只作为导出和备份格式。

## 3. 第一阶段接口契约

### 3.1 MCP 工具

第一阶段的远程 MCP 工具保持窄而稳定，工具内部调用既有 service/repository 逻辑：

1. `fiscal_get_monthly_report`
   - 输入：`period=YYYY-MM`
   - 输出：月度总额、分类分布、账户/负债摘要、异常或缺失提示、`data_revision`。
2. `fiscal_get_yearly_report`
   - 输入：`year=YYYY`
   - 输出：年度汇总及月度趋势，带 `data_revision`。
3. `fiscal_search_ledger`
   - 输入：日期范围、金额范围、分类、账户、关键词、游标。
   - 输出：分页账目和可追溯的原始来源。
4. `fiscal_create_import_batch`
   - 输入：来源（文本/结构化行/图片识别文本）、原始内容摘要、候选账目、客户端幂等键。
   - 输出：`batch_id`、状态、候选数量、输入指纹；只创建待确认数据，不改变正式账本。
5. `fiscal_get_import_batch`
   - 输入：`batch_id`。
   - 输出：候选记录、字段置信度、缺失字段、重复提示、当前版本和可执行动作。
6. `fiscal_validate_import_batch`
   - 输入：`batch_id`、期望版本。
   - 输出：字段/账户/分类/重复校验结果、需要用户回答的问题和可写入数量。
7. `fiscal_commit_import_batch`
   - 输入：`batch_id`、期望版本、确认凭证、幂等键。
   - 输出：写入的交易/现金流对象、跳过项、`data_revision`；重复请求必须返回同一结果。
8. `fiscal_ignore_import_batch`
   - 输入：`batch_id`、期望版本。
   - 输出：已忽略状态和审计信息，不删除原始输入。
9. `fiscal_export_report`
   - 输入：月份或年份、格式（CSV；XLSX 可在同一阶段或紧随其后）。
   - 输出：短期下载引用及导出对应的 `data_revision`。

批量导入以现有 AI proposal 为候选记录的执行基础；新增批次外壳和关联关系，不建立第二套账本。

### 3.2 网页控制台接口/页面

- `/inbox`：批次列表、状态筛选、批次详情、字段修订、重复处理、整批确认/忽略。
- `/reports/monthly`：月份选择、总额、分类、账户、负债、趋势和账目下钻。
- `/ledger`：分页搜索、来源追踪、撤销入口（沿用现有业务约束）。
- `/settings/access`：创建、查看元数据、撤销和轮换 Agent 密钥；密钥明文只在创建时显示一次。
- `/export`：月报/年报 CSV，必要时生成 XLSX。

网页不重新实现财务规则；所有金额校验、写入、撤销和报告口径由后端服务完成。

## 4. 权限和安全模型

- 密钥按用途和 scope 管理：`read:reports`、`read:ledger`、`stage:imports`、`commit:imports`、`export:reports`。
- 默认 Agent 密钥只读或只能创建待确认批次；`commit:imports` 单独授予，并默认关闭自动直写。
- 正式提交需要网页确认凭证或显式的可信 Agent 写入 scope；所有写入必须带 expected version 和 idempotency key。
- 数据库只保存密钥指纹/哈希，支持撤销、轮换、过期和调用审计；日志不得记录完整密钥、账单原文或凭据。
- MCP 端点使用 HTTPS、请求大小限制、速率限制和单用户访问隔离；错误返回不泄露内部表结构。
- Agent 不获得任意数据库查询、schema 变更、账户删除或迁移权限。

## 5. 实施顺序

### 阶段 A：契约和批次基础

- 冻结 Build51 作为原生端基线，登记新方向与非目标。
- 设计 `import_batch` 及其与现有 AI proposal 的关联、状态、版本、指纹和审计字段。
- 定义 MCP 工具 schema、错误码、scope、幂等和确认凭证。
- 复用现有 reports/ledger/AI service，先补批次聚合和批量校验服务。

### 阶段 B：MCP 只读与待确认导入

- 先实现月报、年报、账本搜索和导出工具。
- 再实现创建批次、查看批次、校验批次、忽略批次。
- 用一个真实周账单样本验证：Agent 能一次提交，系统不会提前写账，重复提交可安全重放。

### 阶段 C：网页控制台

- 先做报告和账本只读页面。
- 加入待确认批次页面和字段编辑。
- 加入密钥管理、导出和错误/审计提示。

### 阶段 D：受控提交和试运行

- 实现网页确认后的批量提交和 MCP 提交工具。
- 验证提交、重试、撤销、旧数据报表和 CSV 一致性。
- 连续完成真实月度闭环后，再决定是否撤下原生 App 的发布和维护入口。

## 6. 第一阶段验收标准

- 使用只读密钥的 Agent 能读取月报、年报和账本搜索结果，不能改变数据。
- 使用导入密钥的 Agent 能提交一周账单形成一个批次；批次未确认前正式账本不变。
- 网页能展示缺失字段、重复提示、候选明细并支持整批确认或忽略。
- 同一批次的重复提交、重复确认和网络重试不会产生重复交易。
- 确认后现有月报、年报、CSV 与账本查询能读到同一 `data_revision` 的结果。
- 每次密钥创建、调用、确认、忽略、撤销均可追溯；撤销密钥后不能继续调用。
- 不修改现有 SwiftUI 业务源码、不改变当前生产账本、不移动既有版本标签。

## 7. 待决定项
