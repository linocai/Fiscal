## 1. 目标、顺序与共同禁止项

F5 以当前源码关闭十个真实 macOS runtime gate，再原子替换正式 iOS/macOS root，最后做 unsigned audit draft。严格串行：`F5-A → Independent Review → 修复/复测 → 0 findings → F5-B → Independent Review → 修复/复测 → 0 findings → F5-C → Independent Review → 修复/复测 → 0 findings`。任一 gate、测试或审查未绿，后续块保持锁定；不得以 BFT、模型、SnapshotTool、旧截图、模拟命令或历史结果替代真实 runtime。

- 施工只使用合成 fixture、专门创建的本地 disposable PostgreSQL 与隔离 access key；不得请求生产、部署、生产迁移、备份、真实数据或真实凭证。
- 不切 root、不删旧视觉层、不改 `App/project.yml`、不改 Backend migration/目录，直到 F5-A 终审 0 findings。始终保留用户正在进行的 `apple/ → App/`、`backend/ → Backend/`、`infra/ → Backend/ops/` 迁移；不 reset、checkout、revert、批量整理或混入这些改动。
- V15 Feature 仍只经 typed Foundation seam；只可复用中立 `APITransport`、`AccessKeyStore`、`OfflineSnapshotStore`、`DataRevisionStore`、CNY/Shanghai helper。root 或 V15 Feature 不得回连旧 DTO/repository/视觉 View/`FiscalDesign`。
- `FiscaliOS`/`FiscalmacOS` formal Release 与 audit artifact 一律显式传入 `CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO CODE_SIGN_IDENTITY=""`，只 build、不 launch/install/archive，且不触及 formal production bundle 或其 Keychain。UI runtime 唯一允许启动/安装 `V15Gallery*` 与 QA-only `V15RootSmoke*` 的 Debug/local target；可保留系统必需的 ad-hoc/test signing，但绝不可使用 Developer 或 Distribution identity。QA 要记录 resolved settings、实际 codesign identity、local API、QA bundle/access group/key 来源与非生产数据库；若这些 test target 仍需要 Developer/Distribution identity，立即停止并请求授权。
- QA 只替换更新 `archive/releases/v1.5.0/qa/frontend/f5-results.md`，记录当前 commit-free paths、精确命令、xcresult/截图、非零 test count、环境诊断、审查链和清理结果；本计划与主 Plan 只更新状态。

## 2. F5-A — 运行时恢复与全域审计（唯一解锁 Builder 块）

### 2.1 先恢复测试环境，再判定产品

先从未修改产品/断言的当前源码执行诊断：记录 macOS/Xcode/Simulator runtime、`xcodebuild -version`、可用 destination、自动化/辅助功能授权状态、已有 runner 与每次 xcresult。使用每次新建且可再生的 DerivedData，不把临时绝对路径写入长期计划。禁止通过杀系统守护进程、弱化断言、加 sleep、改 test filter、只 BFT 或重写产品逻辑来“恢复”测试。

共同外部根因仅可在有证据时合并处理：若同一首个 pre-business-test 失败 token 与 runner 状态再次出现，停止扩大重试面，登记一个环境 incident（首次/最近 xcresult、0-step 事实、受影响 gates），先修复本机 automation 环境（例如正常重启、Xcode/Simulator runtime 与授权恢复），再从干净 DerivedData 重启该组。不同 token、或已有非零业务测试后的失败，一律按产品/测试缺陷处理，修复后从该 gate 的全部方法重新执行；不得把十个 gate 统称为一个已关闭事项。

## 3. F5-B — 正式 root 原子切换（F5-A 终审 0 后才可解锁）

### 3.1 受控切换

先以 source scan 写出旧 root 每个可达 destination 到 V15 替代路径及相应 root-smoke/UI evidence 的映射；覆盖 Bootstrap、Record、Ledger、Master Data、Today、Timeline、Credit、Installments、Reimbursements、CashFlow、Reconciliation、AI、Statement Import、Reports 和 Data Security/Archive。映射缺项是 blocker，不可由“旧页仍可访问”掩盖。

在一个不可分割的生产 root 改动中，使 `App/Apps/iOS/FiscaliOSApp.swift → IOSRootView.swift` 与 `App/Apps/macOS/FiscalmacOSApp.swift → MacRootView.swift` 均只启动 production V15 live composition。新增的 V15 AppShell/DI 若需要，放入 `App/Sources/FiscalKit/V15/AppShell/`；它必须由正式 API/access-key/typed V15 services 构造，绝不能复用 `V15GalleryShell`、命令行 fixture/route、synthetic transport 或 Gallery app target。不可在一个平台保留旧 root、另一个平台切 V15；不可改 Backend、schema/migration、用户目录迁移或发布配置。

在 `App/project.yml` 新增或收敛两个 QA-only root-smoke app+UI-test scheme：`V15RootSmokeiOS` 与 `V15RootSmokemacOS`。二者编译**同一正式 root source 与 V15 production DI**，但使用 Debug/local API、独立 QA bundle identifier/access group、临时 QA access key 与合成数据库；不得依赖或启动 Gallery fixture/route/transport。每轮以 Debug test-target `-showBuildSettings`/codesign inspection，在 QA 中证明解析后的 API URL 为 loopback/local、bundle/access group 属 QA target、identity 仅为 system ad-hoc/test signing、key 仅来自隔离 test environment（只记录来源，不记录值）。

只允许这两个 QA-only scheme 真正冷启动并完成 root-smoke：bootstrap/connected/offline、导航全域映射、高风险 read/write 的 server gate、409/unknown、Report export native handoff、Archive exported/disabled-restore 说明。现有 iOS `FiscalUITests` 要替换为针对 `V15RootSmokeiOS` 的非零 V15-root 测试；`V15RootSmokemacOS` 提供同等正式-root macOS UI 测试。`FiscaliOS`/`FiscalmacOS` Release 仍只能以 no-signing **build-only** 编译，绝不作为 launch/install/smoke 入口。若 QA root smoke 不能维持 local/isolated target 或使用了 Developer/Distribution identity，停止并请求授权。

### 3.2 删除仅限已替代的视觉层

只有相同 revision 的双端 root-smoke、替代映射与 `rg` 证明生产 target 不再 reach legacy visual layer 后，才删除旧 `IOSRootView`/`MacRootView` 依赖链中的旧视觉 View、旧视觉 state/nav 与仅服务它们的旧 UI tests。先列 exact delete manifest 和每项替代测试，再删；不作宽泛目录删除。保留中立 transport/storage/auth、CNY parser、Shanghai 日期、必要 DTO compatibility/API 边界及仍被非视觉代码使用的存储。

删除后重跑当前源码的 QA-only formal-root UI、FiscalKit、Gallery 双端、formal no-signing Release build-only/SnapshotTool 和 clean-room。搜索必须证明 production source 无旧 root/旧 visual import、`V15GalleryShell` 引用、`FiscalDesign`、旧 Feature/Repository/`ReportingModel` 的视觉 reachability、死导航或未引用旧 UI test；允许名单只包括已核实的中立兼容边界。编译成功不足以证明删除安全。

### 3.3 回滚与审查

切换前用 `git rev-parse` 解析并在 QA 中记录 v1.4 已发布 tag/commit（预期历史候选 `ad956cd`，实际发布指针为准）和当前候选 source identity。回滚设计是经后续授权选择该已发布 App revision/构件并以前向方式处理 additive API；**不执行** `git reset`、`git checkout --`、database down migration 或对工作树的破坏性操作。

Independent Review 核对 two-root atomicity、真实 DI、映射覆盖、删除 manifest/allowlist、root UI nonzero execution、无 Gallery/旧层 reachability、回滚记录与禁止范围。Builder 修复后重复审查，只有 **0 findings** 解锁 F5-C。

## 4. F5-C — unsigned audit draft（F5-B 终审 0 后才可解锁）

以 F5-B 后的 current source 做一次完整 **unsigned audit draft**：Backend fresh-PG/full/static/migration/Archive/financial-invariant；Apple FiscalKit、QA-only formal-root iOS/mac UI、Gallery iOS/mac、四 no-signing Release build-only、SnapshotTool、视觉/VoiceOver/Reduce Motion human gate；以及 `git diff --check`、cached diff check、root/old-layer/dead-code/secret/path scan。任一 skipped PostgreSQL、0-step UI、未完成 human gate 或 dirty/unidentified source revision 都不能标记 candidate ready。

F5-C Builder（且仅 F5-C）将 `App/project.yml` 的 `MARKETING_VERSION` 从 `1.4.0` 改为 `1.5.0`，并将 `CURRENT_PROJECT_VERSION` 从当前 `23` 顺序递增为建议值 `24`；先以 history 核实 `18198f4` 已占用 build 23，随后 `xcodegen generate`。此版本 bump 不代表发布。对 iOS/macOS 的生成 `Info.plist` 逐项核对 `CFBundleShortVersionString=1.5.0`、`CFBundleVersion=24` 与 manifest 一致；formal audit build 始终 explicit no-signing，QA/Gallery runtime 仅允许本计划定义的 Debug test signing。

当前工作树 dirty/uncommitted 时，source identity 必须记录 `HEAD`、tracked/untracked status manifest、canonical tracked diff + untracked content hash、以及 xcodegen 后 `App/project.yml`/generated project hash；产物只能称 **unsigned audit draft**。仅在现有 Xcode/系统工具范围记录 target/configuration、构件相对路径、resolved build settings、`shasum -a 256` hashes、已执行验证、v1.4 rollback 指针与限制；不 archive、install、codesign、notary 或 export distribution。仓库目前未发现 SBOM 生成器、依赖锁图或既有 SBOM 格式；不得发明或伪造 SBOM，draft manifest 标注 “SBOM unavailable in configured toolchain”。若发布政策要求 SBOM，此项保持 blocking。

Independent Review 独立复算 hashes、核对 draft manifest 与 current source/QA、抽查高风险证据及禁止动作；发现项由 Builder 修复/复测并再次审查。终审 **0 findings** 只可得到“unsigned audit draft verified”。随后明确暂停，等待用户授权 **commit** 后才可针对 clean revision 生成 release candidate；tag/push/sign/notarization/distribution/deploy 仍分别（或用户明确整体）需要新的授权。

## 5. 锁定的发布边界与用户操作

F5 全程禁止签名、notarization、tag、commit/push、分发、deploy、production migration、生产 backup/restore、生产 health/smoke 和真实个人数据验收。F5-C 终审后的 clean-revision candidate 需要先有用户授权 commit；其余发布动作仍需新的当时授权。届时生产网页核验入口为 <https://fiscal.linotsai.top>；当前没有用户网页操作。
